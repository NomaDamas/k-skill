# 국내·해외 기업분석

`company-analysis`는 상장기업의 공개 공시와 발행사 실적발표를 읽고, 실적의 변화와 다음 확인 변수를 **한국어 채팅 메시지**로 정리하는 조회·리서치 스킬이다. 별도 PDF나 보고서 파일은 만들지 않는다. 국내 기업과 해외 기업을 모두 다루되, 로그인 없이 확인할 수 있는 원문이 있는 범위에서만 분석한다.

## 무엇을 보여 주나

출력 제목과 순서는 항상 `1. 요약`, `2. 주요 사업 · 산업 · 경쟁구도`, `3. 최근 사업 현황`, `4. 재무제표 분석`, `5. 실적발표 분석`, `6. Catalyst & Risk`다. 요약에는 조회 시점 표시 주가와 거래·수집 시각을 구분해 넣는다. 재무제표 분석은 손익계산서, 재무상태표, 현금흐름표를 각각 분리하고 비교기간과 최근기간의 수치·변화·의미를 보여 준다. 경쟁사는 공식 원문에서 확인된 이름과 경쟁 축을 적고, 주요 일정은 근거 있는 향후 날짜만 `9/23 · 일정명`처럼 날짜순으로 쓴다.

실적발표의 실제값·사업부별 변화·회사 설명을 우선하며, 발표 전 동일 기간의 집계치가 확인된 경우에만 컨센서스와 비교한다. 목표가, 시장점유율, ROE, FCF 등은 기본값이 아니다. 출처와 정의가 확인된 경우에만 추가한다. 매매 추천은 하지 않는다.

## 자료 경로와 검증

| 시장 | 기본 원천 | 확인할 식별자 |
| --- | --- | --- |
| 한국 | DART 공개 공시 본문, KIND 공개 공시·IR, 발행사 IR | 기업·종목코드, 접수번호, 정정 여부, 기간, 연결/별도 |
| 미국 | SEC EDGAR 공개 제출·XBRL, 개별 10-K/10-Q/8-K, 발행사 IR | CIK, accession, 제출일, 기간, 단위 |
| 그 밖의 해외 | 현지 감독기관·거래소의 공개 공시와 발행사 IR | 법인·증권 식별자, 공시 ID, 기간 |

주가는 재무제표와 별도의 시점 자료다. 한국 종목은 네이버증권 모바일 공개 JSON(비공식 제3자 경로), 미국 나스닥 종목은 Nasdaq 공개 종목 JSON을 사용할 수 있다. 응답 구조, 종목·시장, 거래일/시각을 검증하지 못하면 가격을 `확인 불가`로 둔다. 시세 수집 시각을 체결 시각으로 바꾸어 표시하지 않는다. 두 시세 경로 밖의 시장에서도 검증 가능한 공개 시세가 없으면 같은 방식으로 누락을 표시한다.

수치는 저장한 원문·수집 메타데이터의 SHA-256, 발행일, 원문 인용, 기간·단위·연결 범위를 함께 묶어 검증한다. DART의 하위 재무제표 표는 모공시의 회사명과 접수번호·목차 위치에 연결되는지 검사한다. SEC 수치는 `companyfacts`의 값 하나만 고르지 않고 해당 공시의 accession·기간·단위를 대조한다. 검증기가 내는 고정 형식의 사실 목록은 같은 스냅샷과 원문에서 재현되며, 최종 설명 문장은 그 사실 목록을 바탕으로 작성한다. 원문만으로 확정할 수 없는 숫자는 채우지 않는다.

## 사용과 실패 처리

사용자는 `LG전자를 최신 확정 실적 기준으로 분석해 줘`처럼 기업을 지정하면 된다. 동명이인, ADR과 본주, 복수 종류주식은 먼저 구분한다. 최근 확정·정정 공시의 연결 3대 재무제표, 해당 실적발표, 중요한 최근 변화, 시세를 좁은 범위에서 확인한다. 웹 차단·빈 응답·로그인벽 또는 원문 충돌이 있으면 해당 항목만 `확인 불가`로 표시한다. 세 재무제표 중 하나라도 확보하지 못하면 완성된 분석으로 포장하지 않고 `간이 분석`을 명시한다. 컨센서스가 없으면 그 비교를 생략한다.

`k-dart`는 API 키로 DART 항목을 조회하는 기능이고, `korean-stock-search`는 국내 종목과 일별 시세 조회에 초점을 둔다. 이 스킬은 공개 원문을 기업별로 대조해 채팅 분석으로 종합하며 사용자 로그인·API 키·프록시를 요구하지 않는다. 사용 절차, 스냅샷 형식과 실패 조건은 [`instruction.md`](../../company-analysis/instruction.md)와 [`source-contract.md`](../../company-analysis/references/source-contract.md)에 있다.

## 로컬 검증

```bash
python company-analysis/tests/run_tests.py
node --test company-analysis/tests/evidence.test.js
```

오프라인 테스트는 회사 귀속, 날짜·기간·단위, 원본 해시, DART 모공시 연결, 시세 시점·종목 불일치, 누락 처리, 동일 스냅샷 출력의 재현성을 검사한다. 공개 사이트의 응답과 접근성은 변할 수 있으므로 라이브 조회의 성공률이나 모든 최종 문장의 정확성을 보장하는 테스트로 해석하지 않는다.
